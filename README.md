# nfl_data_bowl_2026

Repository for code used in the 2026 NFL Big Data Bowl competition.

Kaggle writeup: [Win The Duel](https://www.kaggle.com/competitions/nfl-big-data-bowl-2026-analytics/writeups/win-the-duel)

## Win The Duel

This repo implements **"Win The Duel"** — a physics-based **Duel Influence
Probability (DIP)** model that estimates the probability that a
man-coverage defender beats the targeted receiver to a thrown ball, both at
the moment of throw and dynamically while the ball is in flight. It uses
kinematic ball-trajectory estimation and a logistic reach-probability model.
See [writeup/writeup.ipynb](writeup/writeup.ipynb) for the full methodology
(ball trajectory equations, spot-reach probability, the DIP integral) and
[docs/pipeline.md](docs/pipeline.md) for how the writeup's visuals are
generated.

## Repository layout

```
nfl_data_bowl_2026/
├── code/
│   ├── data_bowl_functions.py   # All pipeline logic
│   └── main.py                  # Regenerates the writeup's PNGs/GIFs
├── docs/
│   ├── pipeline.md              # Visual generation pipeline docs
│   └── pipeline_flowchart.md    # Mermaid flowchart of main.py
├── writeup/
│   ├── writeup.ipynb            # Final competition writeup
│   └── ...                      # PNGs, GIFs, MP4s referenced by the writeup
├── data/                        # Raw weekly tracking CSVs (gitignored)
├── logs/                        # Pipeline run logs (gitignored)
├── environment.yaml             # Conda environment spec
└── .env                         # Local config, not committed (see below)
```

`data/` holds the official NFL Big Data Bowl 2026 tracking data. This is
Kaggle competition data, not original to this repo, so it isn't tracked in
git — download it from the competition's Kaggle page and place it in
`data/` before running the pipeline.

## Environment setup

```
conda env create -f environment.yaml
conda activate data_bowl_2026
```

Create a `.env` file at the repo root (never committed) with:

```
WRITEUP_DIR=writeup
SCENARIO_PLAYS=2023092412:3129,2023111207:3086,2023111202:3972
```

## Running the pipeline

To regenerate the reproducible writeup visuals (two summary PNGs and three
scenario play GIFs) from the raw tracking data in `data/`:

```
conda activate data_bowl_2026
python code/main.py
```

This always re-runs the full DIP simulation from scratch and writes its
outputs directly into `writeup/`. See [docs/pipeline.md](docs/pipeline.md)
for what each stage does and which files are produced. Note: the hand-made
full-play GIFs and MP4 files already in `writeup/` are not generated by this
pipeline — there's no code-driven source for them.

Each run logs progress to a timestamped file in `logs/` (and to the
console). A failure rendering one scenario GIF is logged and skipped rather
than aborting the whole run, so the PNGs and any other scenario GIFs still
get produced.
